# Брони и алгоритмы — принятые решения

Брони, смены, метки, оптимизатор, квоты. Живая часть журнала — в `hotel-booking/NOTES.md`.

### Дата смены хранится в БД (не берётся с устройства)
- «Рабочий день» = дата последней смены (`Shift`), меняется **только вручную** кнопкой
  «Следующий день». Нигде не берём дату устройства для бизнес-логики.
- Реализация: `server/src/utils/businessDate.js` (`getCurrentBusinessDate`). Используется
  в гриде, бронях, оптимизаторе, проверке «прошедших дат».

### Метки броней — источник истины в БД
- Модель `BookingFlag` (`code`, `label`, `effects` JSON, `color`, `order`).
- `Booking.flags[]` хранит `code`. Клиент подгружает метки из БД в стор при входе,
  поэтому грид/модалка/оптимизатор работают как раньше (форма `{id,label,effects}`, `id`=`code`).
- Эффекты применяются: в оптимизаторе, при создании и изменении брони (буфер turnaround).

### Система эффектов меток (алгоритм понимает не названия, а эффекты)
- Принцип: метка = ярлык + список **эффектов** из фиксированного словаря. Алгоритм
  работает только с эффектами. Новая метка из существующих эффектов = **0 кода**.
- Текущий словарь: `bufferAfter` (зазор после, напр. поздний выезд=1), `bufferBefore`,
  `pin` (не перемещать).
- Буфер делает двойную работу: запрещает бронь день-в-день + не даёт оптимизатору считать
  этот зазор «окном».

### Оптимизатор: «улучшение от текущей раскладки» (минимум ходов)
- Стартует с реальной раскладки, делает только строго улучшающие ходы (перенос + обмен),
  каждый ход стоит `movePenalty` → предлагаются только осмысленные перестановки.
- Двигает **только не заехавшие** брони (CONFIRMED, не оплачено, не pin, заезд в будущем).
  Заехавшие/оплаченные/ремонт = якоря. Поэтому «переселения гостя» нет — это смена номера
  на бумаге до приезда.
- У каждого хода считается маржинальный эффект «−N окон/ночей» (аннотация, движок не меняет).

### Кнопка оптимизатора возвращена (2026-09-02)
- Скрывали её 2026-06-18 «чтобы случайно не запустить». При редизайне интерфейса
  закомментированную строку не сохранили — кнопки в шапке не осталось вообще,
  и `OptimizeModal` три месяца висел смонтированным без единого способа его открыть.
- Теперь это иконка-палочка в шапке (`ICONS.wand`, тот же значок, что у раздела
  «Оптимизатор» в настройках), рядом со снапшотами и аудитом.
- Проверено на боевых данных: движок отработал, окон 45 → 30, коротких 35 → 13,
  20 перемещений. Совпадает с бэктестом 2026-06-17 (те же данные).
- Случайно применить нельзя: модалка сначала показывает список ходов с галочками,
  применяется только выбранное, плюс перед манипуляцией пишется автоснимок.

### Квоты партнёров — предупреждение, а не назначение (2026-09-08, по итогам аудита)
Аудит показал (D3-003, D5-001, D7-005): `Booking.partnerId` нигде не записывается, поэтому
«бронь партнёра в свою квоту» недостижима, а бронь поверх квоты получает вопрос при каждом
сохранении; из формы новой брони подтвердить продажу нельзя вовсе. Решение — не усложнять:
- Поля «Партнёр» в брони **не будет**. Квота = «номер выделен партнёру X на период».
- При продаже квотного номера спрашиваем **один раз**: «выделен партнёру X, продать всё
  равно?». После подтверждения бронь помечается «поверх квоты», и дальнейшие правки
  вопрос не задают.
- Форма новой брони показывает причину недоступности (квота, буфер метки) и даёт
  подтвердить, а не прячет её за «номер занят».
- **Оптимизатор квотные номера не трогает** — ни в них, ни из них.
- Релизы (частичное освобождение квоты) из поставки убираются: интерфейса у них нет,
  а модель `Release` остаётся на вырост.

### Незаезд — отдельного сценария нет (2026-09-08)
Статус `NO_SHOW` как переход не делаем: гость не приехал — бронь отменяется как обычно.
Метрика «Доля незаездов» и фильтр по статусу — хвост для гигиены, не решение.

### Переезд: два блока в шахматке, один счёт (2026-09-08)
Денежная сторона — в `data-and-money.md` («Деньги при раннем выезде, отмене и переезде»).
Для броней важно: сплит остаётся (две записи, constraint работает как прежде), но вторая
часть ссылается на первую как на счёт, и все денежные экраны считают по цепочке.

**Как переезд делается руками (уточнено владельцем в тот же день, по рисунку):**
- **Перетащил заселённого гостя в шахматке на другой номер — это переезд с рабочей даты, без
  окна.** Полоса «ломается» на дате переезда: первая часть остаётся в старом номере до сегодня,
  вторая — в новом с сегодня; у обеих в точке разлома рваный (зубчатый) край, цвет один. Если
  гость заехал сегодня — бронь переносится целиком. Окно с выбором даты открывается только при
  конфликте по квоте, либо из контекстного меню «Переселить…», когда дату надо выбрать вручную.
- **Сменил номер в форме брони — бронь переезжает целиком от даты заезда**, если номер свободен
  на весь срок (серверный запрет «используйте операцию Переезд» снят). Разлома при этом нет.
- Будущая (не заехавшая) бронь при перетаскивании по-прежнему открывает форму с новым номером.
