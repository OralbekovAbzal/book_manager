### Перенос на новый ноутбук — через копию на флешке, а не база на флешке (2026-09-08)
**Вопрос владельца:** вынести базу на внешний носитель, чтобы при смене ноутбука у клиента
ничего не переносить. **Решение — нет:** живой PostgreSQL на флешке изнашивает её за месяцы
(постоянная запись WAL и контрольных точек), выдернутая во время записи флешка = повреждённый
кластер, нужна NTFS, буква диска меняется между машинами, пароль базы лежит в `config.json`
профиля, а копии рядом с базой — не копии. Вместо этого:
- **Копии сами уезжают на флешку.** Папка копий задаётся в «Настройке системы» (рекомендуем
  флешку/внешний диск). Копия делается ночью в 03:00, **при старте, если последней удачной больше
  20 ч** (`BACKUP_MAX_AGE_HOURS`), **каждые 4 ч работы** (`BACKUP_EVERY_HOURS`) и **при выходе из
  программы** (Electron зовёт `POST /api/system/backup` по внутреннему токену `INTERNAL_TOKEN`,
  который живёт только в памяти процесса и принимается только с loopback). Закрывает аудит D8-003.
- **Флешки нет — копия не пропадает:** пишется в запасную папку на этом компьютере
  (`BACKUP_FALLBACK_PATH`, в Electron — `userData/backups-local`), в `BackupLog` это видно
  (`error: 'BACKUP_PATH недоступна: …'`), в программе — жёлтый баннер «Копия записана на этот
  компьютер: вставьте флешку — при выходе копия запишется на неё». Папку на несуществующем диске
  программа не создаёт. Ротация `BACKUP_KEEP` — в каждой папке отдельно.
- **Новый ноутбук:** установить программу → мастер первого запуска → после создания администратора
  шаг «Перенос данных с прошлого компьютера»: выбрать файл `backup_*.json` с флешки → сводка
  «что восстановится / что исчезнет» с той же галочкой, что в разделе копий → восстановление →
  вход прежней учётной записью (восстановленные учётки заменяют только что созданную). Тот же
  путь доступен позже: «Настройки → Резервная копия → Загрузить файл копии…»
  (`POST /api/system/backup/upload`, до 200 МБ, только SUPER_ADMIN).
- Статус копий: `GET /api/system/status.backup` (`never | stale > 48 ч | fallback | none`) — баннер
  после входа; `GET /api/system/backups.status` — блок в разделе копий (дата, путь, причина).
- **Не делаем:** база на внешнем диске; выбор папки копий из самой программы (остаётся под
  паролем сисадмина); шифрование копий (отдельный вопрос аудита D8-013).

### Многопользовательская работа = локальный сервер в одной сети (2026-06-18)
- **Модель:** один ноут — **хост** (на нём Postgres + Node-сервер), остальные ноуты —
  Electron-клиенты, обращаются к хосту по **локальной сети**. Наружу (в интернет) ничего
  не выставляется — работает только внутри LAN/Wi-Fi гостиницы. Для нашего случая это ок.
- **Почему:** это desktop-программа (не веб-сервис); общая БД нужна, чтобы оба админа
  видели одни брони. Один источник истины = одна машина с базой.
- **Что уже готово:** сервер слушает `0.0.0.0` (`server.js`), broadcast Socket.io летит
  всем клиентам (`socketManager.js`) → realtime между ноутами заработает сам.
- **Что нужно настроить (TODO ниже):** (1) на хосте — статический/закреплённый локальный IP;
  (2) клиент должен знать адрес хоста — сейчас в `client/src/api/client.ts` относительные URL
  (`/api`, `io('/')`), в упакованном Electron они ни к чему не резолвятся → нужно вынести
  base URL в конфиг (напр. `http://<IP-хоста>:3001`); (3) CORS/`CLIENT_ORIGIN` пустить
  origin клиентов; (4) брандмауэр Windows — открыть порт 3001 на хосте.
