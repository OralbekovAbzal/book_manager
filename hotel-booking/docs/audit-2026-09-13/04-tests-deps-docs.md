## 3. Находки подробно

### T13-001 🔴 · `clear.js` стирает рабочую базу без единой проверки

- **Где:** `server/scripts/clear.js:1-15` (весь файл).
- **Факт:** скрипт подключается к базе из `server/.env` (у владельца это рабочая `hotel_booking`)
  и без подтверждения, без имени базы в выводе, без флага `--yes` делает
  `booking.deleteMany()`, `shift.deleteMany()`, `room.deleteMany()`, `category.deleteMany()`.
  Каскады схемы утянут за номерами и категориями всё остальное. Восстановление — только из копии.
  Для сравнения: соседний `demo-seed.js:1248-1262` печатает имя базы, считает существующие
  брони и платежи и **отказывается работать без `--reset`**.
- **Насколько опасно:** одна команда `node scripts/clear.js`, набранная в `server/` вместо
  временной папки (или запущенная агентом, который увидел файл с таким именем), уничтожает
  рабочие данные. В поставку скрипт не попадает (`scripts/**` исключены фильтром сборки), то
  есть клиенту он не грозит — опасен только для машины разработчика и для клона.
- **Предложение:** либо удалить файл (`demo-seed --reset` покрывает тот же сценарий и делает
  это аккуратнее), либо добавить те же три строки защиты, что уже есть в `demo-seed`: печать
  имени базы, обязательный `--yes`, отказ, если имя базы не оканчивается на `_demo`/`_audit`/`_test`.

### T13-002 🟠 · В установщик уезжает ~110 МБ дублей движков Prisma

- **Где:** `electron/package.json` → `extraResources` второй FileSet (`../server/node_modules`);
  результат — `electron/dist/win-unpacked/resources/server/node_modules/`.
- **Факт** (замерено в собранной 13.09 сборке):

| Путь | Размер | Нужен? |
|---|---|---|
| `.prisma/client/query_engine-windows.dll.node` | 19,3 МБ | **да** — им работает Prisma Client |
| `@prisma/engines/schema-engine-windows.exe` | 18,1 МБ | **да** — им работает `migrate deploy` |
| `@prisma/engines/query_engine-windows.dll.node` | 19,3 МБ | дубль |
| `prisma/query_engine-windows.dll.node` | 19,3 МБ | дубль |
| `node_modules/.cache/prisma/**/schema-engine` | 18,1 МБ | кэш загрузки, дубль |
| `@prisma/engines/node_modules/.cache/prisma/**/schema-engine` | 18,1 МБ | кэш загрузки, дубль |
| `@prisma/client/runtime/query_engine_bg.{mysql,sqlite}.wasm` | 4,1 МБ | движки MySQL и SQLite — в проекте только PostgreSQL |
| `@types/{chai,deep-eql,estree,ws,…}` | 3 МБ | следы vitest |

  Итого лишнего ≈ **101 МБ распакованных**; установщик — 204 696 634 байт. NSIS жмёт бинарники
  примерно вдвое, то есть речь о 40–50 МБ установщика.
- **Насколько опасно:** не опасно, дорого. Клиенту, которому ставят программу с флешки, это
  минуты ожидания; при будущем сервере обновлений — трафик на каждое обновление.
- **Предложение:** дописать в тот же `filter`: `!.cache/**`, `!@prisma/engines/node_modules/**`,
  `!@prisma/engines/query_engine-windows.dll.node`, `!prisma/query_engine-windows.dll.node`,
  `!@prisma/client/runtime/query_engine_bg.mysql.*`, `!@prisma/client/runtime/query_engine_bg.sqlite.*`,
  `!@types/**`. Каждый пункт — отдельной строкой и с проверкой на изолированной сборке
  (`HOTEL_BOOKING_USERDATA`), потому что путь к schema-engine Prisma CLI ищет по нескольким
  местам: убрать не тот дубль значит сломать миграции у клиента.

### T13-003 🟠 · 200 МБ тела разбираются до проверки, кто это

- **Факт:** парсер подключён на уровне приложения и ДО `maintenanceGate`, `auditMiddleware`,
  `apiLimiter` и `authenticate`. Любой, кто видит порт (в упакованной сборке — 4780,
  `HOST=0.0.0.0`, правило брандмауэра открыто установщиком), может слать `POST` c телом до
  200 МБ: Node прочитает и разберёт его в память, и только потом роут ответит 401.
  Ограничитель частоты на этот путь не действует — он висит на `app.use('/api/system', apiLimiter, …)`,
  то есть ниже по цепочке.
- **Насколько опасно:** несколько параллельных запросов по 200 МБ кладут процесс сервера по
  памяти. Сценарий требует доступа к сети отеля (гостевой Wi-Fi, если он не отделён от
  служебного). Electron поднимет сервер заново, но при повторении стойка останется без программы.
- **Предложение:** поставить `authenticate` (и `requireRole('SUPER_ADMIN')`) перед парсером —
  отдельным `app.use('/api/system/backup/upload', authenticate, requireRole(…), express.json(…))`;
  либо прикрыть путь своим `rateLimit` до парсера. Правка — одна строка в `app.js`, но это
  чужая зона: решение за направлением «сервер».

### T13-008 🟠 · Повторный переход суток двигает дату ещё на день

- **Где:** `server/src/controllers/shiftController.js:75-90`.
- **Факт:** `nextDate = currentDate + 24 ч`, где `currentDate` — дата ПОСЛЕДНЕЙ смены. Дальше
  `prisma.shift.upsert({ where: { date: nextDate } … })` с комментарием «create if not exists,
  do nothing if already exists». Комментарий вводит в заблуждение: ключ всегда указывает на
  дату, которой ещё нет, поэтому `upsert` всегда создаёт. Идемпотентности нет.
- **Вход, который её вызывает:** два `POST /api/shifts/next-day` подряд — двойное нажатие,
  повтор после таймаута сети, или два рабочих места, подтвердившие один и тот же диалог.
  Результат: рабочая дата ушла на двое суток вперёд.
- **Насколько опасно:** назад дороги нет. Рабочая дата — это `max(Shift.date)`, роута на
  удаление или сдвиг смены не существует; чинится только правкой в базе. При этом от рабочей
  даты зависит всё: какие брони «сегодняшние», можно ли заселять, что показывает шахматка и
  касса. На клиенте защита есть (`AuditWindow.tsx:231-237` — `window.confirm` с конкретной
  датой и словами «Вернуться назад будет нельзя»), у API — нет.
- **Тест:** `audit13-coverage-gaps.test.js` → «повторный запрос перехода не двигает сутки отеля
  дважды» (`it.fails`).
- **Предложение:** принимать `expectedDate` в теле и отвечать 409 при расхождении — тот же
  приём, что уже работает у брони (`expectedUpdatedAt` → `BOOKING_STALE`). Клиент знает
  текущую дату смены, менять форму почти не придётся.

### T13-009 🟠 · С истёкшим пробным периодом нельзя снять копию своих данных

- **Где:** `server/src/middleware/license.js:28` (`ALLOWED = ['/api/health', '/api/license', '/api/auth/login']`).
- **Факт:** при `TRIAL_EXPIRED` и `MAINTENANCE_EXPIRED` всё, кроме этих трёх путей, отвечает
  402. Под запрет попадают `POST /api/system/backup`, `GET /api/system/backups` и
  `POST /api/system/backup/restore`, а также любой отчёт и экспорт.
- **Насколько опасно:** текст гейта обещает «Данные не тронуты» — и это правда, но забрать
  их отель не может ничем, кроме `pg_dump` руками. Для покупателя, который решает «брать или
  не брать», это худший вид разговора: «программа не даёт выгрузить мои брони». Автоматические
  ночные копии при этом продолжают идти (они не проходят через HTTP), то есть файл на флешке
  есть — но узнать об этом из программы нельзя.
- **Предложение:** решение владельца, не техническое. Минимум — добавить в `ALLOWED`
  `GET /api/system/backups` и `POST /api/system/backup`, чтобы с экрана блокировки можно было
  нажать «Сделать копию» и увидеть, где она лежит.

### T13-012 🟡 · Количество в ручной строке начисления без потолка

- **Где:** `server/src/routes/bookings.js:214-216` (`chargeMoneyRules`).
- **Факт:** `unitPrice` ограничена `{ min: -100000000, max: 100000000 }`, а `quantity` — только
  `{ min: 0 }`. `POST /api/bookings/:id/charges` с `quantity: 1e15, unitPrice: 100000000`
  проходит валидацию; контроллер (`bookingController.js:1599`) отбивает только `Infinity`
  (`Number.isFinite`), а 1e23 — число конечное, колонка `Float` его примет.
- **Насколько опасно:** невелико — нужен вошедший администратор и очень странный ввод. Но
  строка, которую нельзя «исправить обратно» (итог считается суммой строк, и после такой
  записи он теряет точность у обычных сумм), чинится только удалением строки. Заодно это
  напоминание, что деньги в схеме — `Float`, а не `Decimal` (вопрос направления «деньги»,
  не мой).
- **Тест:** `it.fails` «количество в ручной строке ограничено сверху так же, как цена».
- **Предложение:** `isFloat({ min: 0, max: 100000 })` — больше ста тысяч единиц одной услуги
  в брони не бывает.

## 7. Что выглядит надёжно

- **Прогон тестов.** 1409 зелёных за 6,4 с, три прогона без единого расхождения, включая прогон
  под UTC+14. Ни одного `skip`. Для проекта, где половина логики — даты, это лучший показатель
  из всего, что я смотрел.
- **Инструменты тестов.** `fakePrisma` с настоящим вычислителем `where` (неизвестная операция —
  исключение, а не молчаливый пустой результат) и `loadCjs` с `append` — за счёт второго
  оказалось возможно покрыть валидаторы роутов без supertest и без базы. Ни один тест не
  требует живой базы.
- **Защита от мусора в деньгах.** `Number.isFinite` на сумме начисления, лимит возврата
  «не больше принято», `pinLegacyTotal` перед первой ручной строкой, запрет `kind: refund`
  без `refundOfId` — все четыре стоят в коде, а не в комментариях.
- **Резервные копии.** `readDump` проверяет имя файла регуляркой И `path.basename(name) === name`
  (обход каталога закрыт дважды), `safeImportName` чистит имя из заголовка, версия формата
  сверяется отдельной функцией, ротация не трогает принесённые `imported_*`. Покрыто тремя
  файлами тестов.
- **Границы дат в предметной области.** Полуоткрытые интервалы выдержаны единообразно:
  брони, квоты партнёров (`dateFrom < to && dateTo > from`), релизы, ночи в отчётах
  (`eachNight` = `[from, to)`). Проверил четыре независимых места — расхождений нет.
  Квота встык к соседней конфликтом не считается — проверено тестом.
- **Скрипт демо-данных** — образец того, как должен выглядеть опасный скрипт: имя базы в выводе,
  подсчёт существующих данных, обязательный флаг, сохранение учётки, детерминированный
  генератор. `clear.js` рядом с ним выглядит особенно голым.
- **Установщик** не содержит `.env`, ключей, тестов и инструментов сборки — то, что закрывали
  волной 10, держится.
- **Лицензии зависимостей** — ни одной GPL/AGPL-only на 327 пакетов поставки.
