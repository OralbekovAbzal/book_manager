### D5-002 · [Тяжесть 2] Клиентский итог перезаписывает сумму строк при правке только предоплаты / полей инвалидности
- Направление: 5 · Класс: деньги
- Окружение: оба
- Где: `client/src/utils/calculator.ts:87-94` (ключ входов — 13 полей, включая `prepaymentPercent`, `disabledAdults`, `disabledChildren`); `client/src/components/BookingModal/BookingModal.tsx:1313-1318` (`inputsChanged → sendTotals → includeTotals`), `:1413-1415` (`totalAmount`/`prepaidAmount` в payload); `server/src/utils/charges.js:347-351` (`CHARGE_INPUT_FIELDS` — 10 полей, без этих трёх); `server/src/controllers/bookingController.js:519-521` (`needsRebuild`), `:545-546` (`totalAmount`/`prepaidAmount` пишутся как пришли, без пересборки).
- Что: ключ клиента шире серверного. Изменение только предоплаты или счётчиков инвалидности заставляет форму отправить `totalAmount = calcResult.totalAfterDiscount` (предпросмотр по тарифу, без ручных строк и без серверных правил базы скидки), а сервер пишет это число, не пересобирая строки → `Booking.totalAmount ≠ Σ BookingCharge.amount`.
- Сценарий (числа): бронь 3 ночи × 20 000 = 60 000 (auto) + ручная строка «Поздний заезд» +5 000 → Σ строк 65 000 = `totalAmount`. Администратор открывает бронь и меняет предоплату 50 % → 30 %. Клиент: ключ изменился → шлёт `totalAmount: 60000, prepaidAmount: 18000`. Сервер: `chargeInputsChanged` = false, `services` те же → `needsRebuild = false` → в базе `totalAmount = 60 000` при Σ строк 65 000. Касса (`bookingMoney`, `chargesFromRows`) показывает «Начислено 65 000», сетка и «Сохранённая сумма брони» — 60 000. Со скидкой расхождение больше: те же строки + скидка 10 % → сервер считал 6 500 (итог 58 500), клиент — 6 000 (итог 54 000) → `totalAmount = 54 000`.
- Проверка: воспроизвести сценарий на клоне; `SELECT b.id, b."totalAmount", (SELECT round(sum(c.amount)) FROM "BookingCharge" c WHERE c."bookingId" = b.id) AS rows_sum FROM "Booking" b WHERE b.id = <id>;` Код: сравнить `buildCalcKey` и `CHARGE_INPUT_FIELDS`.
- Последствия: два разных «итога» на экране (форма/сетка/печать против кассы); долг в кассе считается по строкам и не теряется, но `totalAmount` врёт до следующей правки дат/гостей.
- Уже известно: нет (план: зацепка «ключ пересчёта 13 vs 10 полей»)
- Связано с: D2 (`PUT /bookings/:id` принимает `totalAmount`/`prepaidAmount`/`paidAmount`), D5-020, таблица §2.1
- Уверенность: подтверждено

### 2.1 Предпросмотр (`calculator.ts` + `serviceLines.ts` + `BookingModal.calcResult`) ↔ генератор (`charges.js`)

Что совпадает: посуточное округление `Math.round` по ночи и по строке услуги; «ноль — не цена»
(ночь/услуга без цены строки не порождает: `calculator.ts:161-168` ↔ `charges.js:131-132`,
`serviceLines.ts:140` ↔ `charges.js:165`); `childPrice = null` → взрослая цена
(`serviceLines.ts:136-137` ↔ `charges.js:161-162`); единицы `per_person_night / per_night /
per_person / per_booking` (`serviceLines.ts:145-161` ↔ `charges.js:178-194` — дословный дубль);
сложение гостей `WithMeals + NoMeals` (`BookingModal.tsx:1397-1403` ↔ `charges.js:48-54`);
предоплата `round(итог × %)` (`calculator.ts:183`, `BookingModal.tsx:1251` ↔ `charges.js:268`);
неактивная услуга пропускается обеими сторонами.
