### C13-001 🟠 «Скачать копию номерного фонда» в упакованной программе молча не работает
`components/Settings/sections/BackupSection.tsx:86-97`
```js
const url = URL.createObjectURL(blob)
const a = document.createElement('a')
a.download = `номерной-фонд-${stamp}.json`
a.click(); document.body.removeChild(a); URL.revokeObjectURL(url)
setStatus({ kind: 'ok', text: `Сохранено: ${cats.length} категорий, ${rooms.length} номеров…` })
```
- **Сценарий:** установленная программа (окно на `file://`), Настройки → Бэкап → «Скачать
  резервную копию». Загрузка по ссылке на `file://` не работает — это уже записано в проекте
  (`api/reports.ts:366-391` и `Reports/editor/model.ts:206-212` специально ходят через мост
  `window.appConfig.saveReportFile`). Здесь моста нет.
- **Ожидаемое:** файл выбирается нативным диалогом; если сохранить не удалось — красный статус.
  Сейчас на экране зелёное «Сохранено: 5 категорий, 46 номеров», а файла нет.
- Плюс `revokeObjectURL` зовётся синхронно сразу после `click()` (в двух других местах — через
  `setTimeout(…, 1000)`): даже в браузере это может оборвать загрузку.
- **Предложение:** повторить ветку из `downloadReport` — при наличии `window.appConfig.saveReportFile`
  сохранять через мост, иначе ссылкой, и статус «ok» ставить только по факту успеха.

### C13-002 🟠 «Выйти» отзывает все сессии учётной записи
`store/useAuthStore.ts:119-135` → `POST /auth/logout` → `authController.logout` → `revokeSessions(admin.id)`
- **Сценарий:** два рабочих места вошли под одной учёткой (для базы отдыха на 70 номеров это
  обычная жизнь — одна «admin» на стойке и в кабинете). Первый сотрудник в конце смены жмёт
  «Выйти» → сервер поднимает `tokenVersion` → второму приходит `auth:revoked session_revoked` →
  `logout()` размонтирует приложение вместе с заполненной формой брони. Никакого предупреждения.
- **Ожидаемое:** выход закрывает свою сессию; чужие живут до своего срока. Либо (если отзыв всех
  сделан намеренно) — подтверждение «Выйти со всех рабочих мест? Сейчас работает ещё N».
- **Предложение:** отзывать текущий токен (список сессий/jti) либо добавить `ConfirmDialog` перед
  выходом с текстом про другие рабочие места.

### C13-005 🟠 Свой пароль сменить нельзя
На сервере есть `POST /api/auth/change-password` (`routes/auth.js:23`, для любого вошедшего),
в клиенте нет ни вызова, ни экрана (`grep -r change-password client/src` — пусто). Сброс пароля
живёт в «Пользователях», а туда пускает только SUPER_ADMIN (C13-004).
- **Сценарий:** владелец завёл сотрудника с временным паролем; сменить его сотрудник не может —
  надо звать владельца. Для продажи это первый же вопрос на внедрении.
- **Предложение:** карточка «Мой пароль» в «Настройки → Пользователи» (виден себе всегда) или в
  «О программе»: текущий + новый, правила уже есть в `Setup/accountRules.ts`.

### C13-008 🟠 Четыре формата денег, два из них округляют
- `ChargesPanel.tsx:17` — `Math.round(n)` (строки начислений);

- **Предложение:** один модуль форматирования денег (округление до тенге — решение владельца,
  но одно на все экраны), отчётные итоги считать по тем же округлённым значениям.

### C13-011 🟠 Цена 0 принимается как настоящая цена
`Rates/RatesScreen.tsx:223-234` — проверка только `value < 0`; `missing` (`:150-156`) считает
дырами лишь `null`.
- **Сценарий:** в поле массового заполнения набрали «0» (или очистили и нажали Enter) —
  записывается 0 для всех выделенных ячеек. На календаре «0», счётчик «без цены» не растёт, а
  предпросмотр брони считает ночь в ноль и говорит «цена не задана» только для `null`.
- **Предложение:** спрашивать подтверждение на нулевую цену («ночь будет стоить 0 ₸») или
  трактовать 0 как очистку — решение владельца, но текущий вариант молчит о нём в трёх местах.

## Что выглядит надёжно

- **Деньги считает только сервер.** В теле `PUT/POST /bookings` нет ни итога, ни предоплаты, ни
  «оплачено»; предпросмотр и сохранение — один код. Поле «Оплачено» в форме — только чтение.
- **Замок версии.** `expectedUpdatedAt` + тихая сверка редактируемых полей + диалог
  «Перечитать / Продолжить» — редкий случай, когда конфликт объяснён человеческим языком.
- **Realtime.** Один тик (`useRealtimeStore`) вместо пяти подписок; `broadcast` после обрыва;
  панель оплаты не подменяет набранную сумму, а пишет «Долг изменился: N».
- **Даты.** `@db.Date` везде режутся строкой или рендерятся с `timeZone:'UTC'`; фактические
  моменты — местным временем. Проверены все 28 мест форматирования — расхождений не нашёл.
- **`ui/ConfirmDialog`.** Перехват Esc/Enter на `window`, ловушка фокуса Tab, фокус на «Отмена»
  при `danger` — сделано лучше, чем в большинстве коммерческих админок.
- **Печать документов.** Отдельный `@page portrait`, принудительные `#fff/#000` на листе,
  `display:contents` у оверлея, Esc в фазе перехвата, PDF через мост Electron.
- **Копии базы.** Сводка последствий до подтверждения, запасной путь при недоступном `/impact`,
  разделение прав, состояние папки копий и свободного места из одного стора.
- **FEATURES.** Оптимизатор и откат к снимкам недостижимы: роутера в приложении нет вовсе,
  единственные входы (кнопки шапки, пункт настроек, монтирование модалок) закрыты флагом, а
  сервер отвечает 404 независимо от клиента.
- **Типы.** `npx tsc --noEmit` — чисто.

## Что проверить глазами на живом стенде

Клон `hotel_booking_audit` (3012/5175) или демо-база; упакованную сборку — в изоляции по
`HOTEL_BOOKING_USERDATA`.

1. **Esc в календаре формы брони.** Новая бронь → заполнить имя, телефон, паспорт → открыть
   «Дата заезда» → Esc. Ожидание находки C13-003: закроется вся форма, введённое пропадёт.
2. **Esc в списке номеров.** То же, но открыть выпадающий список номеров (C13-020).
3. **Скачивание номерного фонда в установленной программе.** Настройки → Бэкап → «Скачать
   резервную копию». Смотреть: появилось ли зелёное «Сохранено» и есть ли файл на диске (C13-001).
   В браузере на 5175 то же самое должно работать — разница и есть находка.
4. **Общая учётка на двух местах.** Войти под одной учёткой на двух окнах, на первом открыть форму
   брони и заполнить, на втором нажать «Выйти». Ожидание: первое место выкинет на экран входа с
   «выполнен выход на другом устройстве», форма потеряна (C13-002).
5. **Администратор в «Пользователях».** Войти сотрудником с ролью «Администратор» → Настройки →
   Пользователи. Ожидание: «Недостаточно прав» (C13-004). Там же проверить, есть ли вообще способ
   сменить свой пароль (C13-005).
6. **Касса: сумма с пробелом.** Выбрать бронь с долгом, стереть подставленную сумму, набрать
   «10 000» → «Принять». Ожидание: «Сумма должна быть больше нуля» (C13-007).
7. **Строка начисления с пустой ценой.** Форма брони → Начисления → правка строки → стереть цену,
   вписать причину → «Сохранить». Ожидание: строка станет 0 ₸ без предупреждения (C13-006).
8. **Копейки.** Поставить скидку, дающую дробный итог (например, 12,5 % от 18 500), и сравнить
   число в «Начислениях», в «Итого по строкам» и в отчёте «Выручка» (C13-008).
9. **Цена 0 в тарифах.** Выделить пару ячеек, ввести 0, применить. Смотреть счётчик «без цены» и
   предпросмотр брони на эти даты (C13-011).
10. **Фильтр по корпусу.** Выбрать корпус Б → «Применить» → открыть список корпусов. Ожидание:
    в списке только Б (C13-012).
11. **Ошибка загрузки кассы.** Остановить сервер, открыть «Касса → Приём оплаты» (или обновить
    список). Ожидание: «Ничего не найдено» вместо сообщения об ошибке (C13-009). То же для
    «Тарифы → Цены» — пустой красный календарь (C13-010).
12. **Печать отчёта в тёмной теме.** Переключить тему, открыть любой отчёт → «Печать» →
    предпросмотр печати. Ожидание: заголовка отчёта на листе не видно (C13-013).
13. **Тёмная тема в форме брони.** Открыть бронь в тёмной теме: белые кнопки «−/+», светлые
    плашки «Номер свободен», жёлтая плашка квоты (C13-014).
14. **Переход на следующий день.** «Аудит» → «Следующий день»: нативное окно подтверждения без
    числа незакрытых выездов; при отказе сервера — общий текст (C13-015).
15. **Окно 1366×768 и масштаб 125 %.** Проверить форму брони (обе колонки, кнопки внизу), «Кассу»
    (две панели), «Тарифы» (календарь на 31 день), «Отчёты» (тулбар из шести кнопок) и мастер
    первого запуска. Смотреть: не уезжают ли кнопки за край, не появляется ли двойная прокрутка.
16. **Длинные имена.** Гость «Абдрахманов-Сулейменов Абдулла Рахимжанович» и категория с длинным
    названием: полоска в шахматке, строка в кассе, плашка цепочки, печать счёта.
17. **Ошибка сетки.** Остановить сервер и нажать «Повторить» в шахматке: ожидается английский
    «Network Error» (C13-016).
18. **Производительность.** База с 60 номерами × 45 дней: открыть контекстное меню на броне,
    подвигать выделение мышью, открыть/закрыть форму. Смотреть на задержку отрисовки (C13-017).
19. **Конец пробного периода.** `ROOMLINE_TRIAL_DAYS=0` на клоне: заполнить форму брони и дождаться
    первого запроса. Ожидание: экран блокировки вместо приложения, форма потеряна (C13-028).
20. **Повторный вход.** Дождаться истечения токена с открытой формой, ввести пароль. Проверить, что
    введённое на месте, и посмотреть, осталась ли красная ошибка про токен (C13-029).
